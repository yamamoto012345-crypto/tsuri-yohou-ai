# 釣り予報AI

日時・場所・釣種を入力すると、気象データ（Open-Meteo）と簡易潮汐モデルから
「ベストな釣り方3選」とマップ位置を提案するスマホ対応PWA（Progressive Web App）。

## 構成ファイル

| ファイル | 役割 |
| --- | --- |
| `index.html` | 入力フォーム・結果表示のUI（Tailwind CSS） |
| `style.css` | 独自スタイル（アニメーション・配色補正） |
| `app.js` | ジオコーディング・気象/潮汐取得・診断アルゴリズム・地図描画（Google Maps / Open-Meteo連携） |
| `manifest.json` | PWAのアプリ情報（アイコン・テーマカラー・起動設定） |
| `sw.js` | オフライン対応のService Worker |
| `icons/icon.svg` | アプリアイコン |

## ローカルでの動作確認

ビルド不要。静的サーバーで配信すれば動作する（Service Workerは`file://`では動かないため
必ずHTTP経由で開く）。

```bash
python -m http.server 8000
```

ブラウザで `http://localhost:8000/index.html` を開く。

## 使い方

1. 釣種・日時・時間帯・釣り場所（地名/住所）を入力
2. 「ベストな釣り方を診断する」を押すと、地図とおすすめ3パターンが表示される
3. （任意）詳細設定にGoogle Maps APIキーを入れると地図がGoogle Mapsに切り替わる。
   未入力ならOpenStreetMap（無料・キー不要）で表示する

## 使用API・データソース

- **ジオコーディング**: Nominatim（OpenStreetMap）。日本語の地名・住所を検索できる無料API。
  公開デモサーバーには利用制限（fair use, 概ね1req/秒）があるため、アクセスが多い本番運用では
  自前ホスト or 有料ジオコーダーへの切替を推奨。
- **気象データ**: Open-Meteo forecast/archive API（気温・気圧・風速風向・天気）。
  予報は概ね16日先まで。それより先の日付は直近の予報データで近似表示する。
- **海面水温（海釣り/ショアジギング）**: Open-Meteo Marine API。毎回そのタイミングの実測値を
  取得し、「低水温期」の判定に使う（対応範囲: 直近5日前〜16日先）。内陸座標など海に面していない
  場合はデータが信頼できないため取得せず、後述のカレンダー判定にフォールバックする。
- **気温トレンド（ブラックバス/渓流・トラウト）**: 海面水温の代わりに、Open-Meteo forecast API の
  直近5日間の日平均気温を取得して平均し、「今season実際に暖かい/寒いか」の目安にする。
- **潮汐**: 正式な観測データではなく、月齢から算出した簡易近似モデル
  （大潮/中潮/小潮・上げ下げ・満干潮時刻の目安）。実際の潮汐表とは異なる場合がある。

### 「低水温期」判定のロジック（気候変動対応）

診断ロジックの一部（カバー撃ち・ボトムトレース・スロージギング等）は「低水温期かどうか」で
加点している。暖冬や早い寒波などカレンダーとズレることがあるため、以下の優先順位で
毎回そのときの実測・準実測データを使う。

1. 海釣り/ショアジギング → 実測の海面水温 < 15℃
2. ブラックバス/渓流・トラウト → 直近5日間の平均気温 < 10℃
3. 上記が取得できない場合のみ → カレンダー上の月（11〜3月）で簡易判定

結果カードの「選出理由」に、どの根拠を使ったか（実測水温／気温トレンド／カレンダー）を
明記している。

### 広域エリア→詳細ポイントの選出（琵琶湖・淡路島など）

「琵琶湖」「淡路島」のような広域名を入力すると、エリア内の詳細ポイントを3件選出し、
マップに複数ピンを表示する。

- **キュレーション済みエリア**（現在は琵琶湖・淡路島）: 実在する有名スポットを手動で
  データベース化したもの（`app.js`内`CURATED_AREAS`）。座標・特性は目安であり、
  最新の釣果情報や現地の規則を反映したものではない。
- **その他の広域エリア**: Nominatimの範囲(bounding box)から機械的に「岸寄り/沖合い/中間」の
  3エリアを生成する（実績データに基づくものではないことをカード内に明記）。
- 範囲が十分狭い地点（住所・施設名など）はこの処理をスキップし、従来通り単一地点で
  ベストな釣り方3選を表示する。

## 既知の制限（プロトタイプ）

- 潮汐は簡易推定であり、港ごとの実測潮汐表とは差が出ることがある。
- ジオコーディングが同名の店舗・施設を港/湖より上位に返すことがあるため、
  ヒットしない/意図しない場所が出た場合は「〇〇市」「〇〇川」など地名を変えて試す。
- 広域エリアの詳細ポイント（琵琶湖・淡路島以外）はキュレーションではなく機械生成の
  目安位置であり、実際の釣果実績に基づくものではない。
- Google Maps APIキー未設定時はOpenStreetMap表示。キーを設定して初めて実際の
  Google Maps JavaScript APIが読み込まれる（課金・利用規約はユーザー自身の責任）。
- 診断ロジックはルールベースのスコアリング（風速・天候・時間帯・潮汐・水温トレンド等の
  加点方式）。釣果を保証するものではなく、あくまで参考情報。

## GitHub Pagesで公開する手順

このリポジトリはビルド不要の静的ファイルのみなので、`main`ブランチのルートから
直接公開できる（別途`gh-pages`ブランチを用意する必要はない）。

1. GitHub上でリポジトリを開き、**Settings** タブを開く
2. 左メニューの **Pages** を選択
3. 「Build and deployment」の **Source** で **Deploy from a branch** を選ぶ
4. **Branch** に `main` を選び、フォルダは `/ (root)` のまま **Save**
5. 数十秒〜数分待つと、ページ上部に公開URL
   （`https://<GitHubユーザー名>.github.io/<リポジトリ名>/`）が表示される
6. そのURLに`index.html`を含めず（末尾スラッシュのまま）アクセスすればアプリが開く

### スマホのホーム画面に追加する

- **iPhone (Safari)**: 公開URLを開く → 共有ボタン → 「ホーム画面に追加」
- **Android (Chrome)**: 公開URLを開く → 右上メニュー → 「ホーム画面に追加」/
  自動的に表示される「アプリをインストール」バナーをタップ

ホーム画面のアイコンから起動すると、アドレスバーのないアプリ風の画面（standalone表示）で
起動する。

### 更新を公開に反映する

`main`ブランチにpushするだけで、GitHub Pagesが自動的に再ビルド・再公開する
（反映まで1〜2分程度）。
